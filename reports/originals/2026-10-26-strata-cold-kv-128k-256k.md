## Definitions and limits

The 128K group has 131072 input tokens plus at most 4096 output tokens. The native service keeps a 262144-token window throughout; this is not a comparison against a server restarted at 128K capacity. The 256K group has 258040 input + 4096 output + 8 internally reserved tokens = 262144. Early EOS would be retained separately; a configured limit is not treated as observed full-window use.

The same five-key archive retrieval and long SQLite-generation workload is repeated, changing the leading nonce and five keys each time; all 20 first32-ID hashes differ. Settings: temperature 0, top_p .95 / top_k 20, thinking none / enable_thinking false. The model is preloaded. Cold KV does not imply cold OS weight pages; even the first trial excludes model loading.

TTFT starts immediately before client HTTPConnection.request, after serialization, and ends when the first nonempty text/reasoning SSE arrives. Each received line is timestamped before parsing or disk writes. Empty role, keepalive and usage chunks do not count. TTFO ends at the first non-reasoning content; with no actual reasoning it should equal TTFT. Only local exact token fitting occurs beforehand; server count-only confirmation follows measurement, with usage checked independently.

Native prefill is this request's SSE prompt_n divided by prompt_ms converted to seconds; native decode is predicted_n divided by predicted_ms converted to seconds. Pooled rates divide total tokens by total corresponding seconds, rather than averaging request rates arithmetically. The summary also retains per-request rate means, medians and ranges. Historical cached tokens and stale global timings are not substituted.

Each request has a 900-second deadline; there are no failed-sample replacements or retries. One short warmup and one final recovery control are separate from the 20-request summary. Fixed 128K-then-256K order, background load, MTP acceptance and repetitive SQL may affect results. This does not establish a single-factor engine effect or general model capability.

## Independent post-run verification

Total elapsed time was 79.83 minutes, from 10:31 to 11:51 local time on 2026-10-26. All 20/20 formal requests returned HTTP 200, with no retries, replacements, early EOS or cache contamination. Final short-request recovery passed; the original service processes, 262144-token window and vision capability remained. Five-key accuracy of 100/100 applies only to this synthetic retrieval workload, not general reasoning or code quality. Every long SQL output ended at the 4096-token limit; this does not claim completion of all requested SQL.

Offline replay of all 20 SSE records rechecked TTFT/TTFO, output, usage, native timings, request/output SHA, post-measurement input counts, window budgets, five keys, configuration/binary SHA and group statistics: 275/275 checks passed. The local audit script and machine results remain with the original run; the published evidence includes curated audit results. The formal runner and protocol were unchanged; the local freeze commit is `8aa16f9`.

All 4762 samples reported normal pressure, with no telemetry errors or sampler exceptions. Mean interval was 1.006 seconds; maximum was 1.038 seconds. The first and peak swap readings from the same sysctl source were both 2935163453.44 bytes, for observed growth of 0. Raw swap_delta_bytes retains a roughly 2621.44-byte fixed offset from mixing a psutil baseline with rounded sysctl values. The table displays 0.000 GiB; that rounding offset is not treated as actual swap growth. Raw data were not changed.

Across trials, 128K TTFT rose from 91.30 to 129.26 seconds, while the later 256K trials fell from about 265–273 to 233.40 seconds. Fixed execution order, background load and missing temperature measurements remain limitations; the trend alone does not establish thermal throttling or an engine speedup mechanism.
