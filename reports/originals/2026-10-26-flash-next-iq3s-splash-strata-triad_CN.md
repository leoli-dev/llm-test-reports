测试及独立评审：2026-10-26，America/Toronto。相同 M5 Max 本机推理。六组模型运行均完成；仅本地提交，没有 push。

## 实测结论

Splash 1.4.1 的专家与 PLE 全驻留模式，是本次实际测试的两种 Splash 配置中最快的。受控冷 KV 编程探针中，decode 为 157.42 token/s，Strata 为 83.36，约 1.89×；首个生成事件平均 3.785s 对 7.796s。代价是更高的全机内存占用。这是本轮已测配置中的最佳结果，未穷举 M5 Max 所有优化组合。

| 产品 / 100 | Splash | Strata | 主要验收限制 |
|---|---|---|---|
| 电影网站 | 72 | 70.75 | 两者在线元数据不完整；Splash 泄漏隐藏搜索结果，Strata TMDB 导入失败。 |
| 方块游戏 | 83 | 80 | Splash 高空修改不可见；Strata 测试世界无水且读档重置敌人血量。 |
| 动态清明上河图 | 63 | 61 | 两者可动画和浏览，但接近原作的程度仍低。 |

评分来自身份可见的独立评审，采用预先固定的 85 个标准，每项任务与引擎只有一份作品。几分之差不足以建立通用模型或引擎质量排名。三个实际代理工作负载中 Splash 的原生 decode 都更快，但完成时间和缓存命中后的首事件延迟并未统一改善。评审者没有修复产品源码。

## 安装、模型对等性与 M5 Max 调优

准备时记录的上游最新版本为 Splash 1.4.1。固定源码版本后执行 `make -j6` 和上游 `make install-environment`，受版本控制的上游文件保持干净。遵循本机仓库布局：运行时位于 `~/local_llms/splash`，目标、draft 与组装模型位于 `~/local_llms/models/splash`，配有 `start.sh`、`stop.sh`、`status.sh`、`serve.sh` 生命周期脚本。本机生成的认证文件权限为 0600，归档不包含认证。没有自动启动。

两个目标 GGUF 分片和 BF16 视觉投影器通过 APFS 写时复制克隆到独立 Splash 目录，inode 不同，没有硬链接或符号链接指向 Strata。完整 SHA256 与 Hugging Face LFS 一致。使用公开的 `install.local.prepare_local_model` API 组装本地分片、投影器与 draft；没有替换成更低量化、Coder 裁剪模型或此前的 27B 8bit 模型。

“IQ3_S”是发布者的混合格式量化标签。头部检查发现 20 个 IQ3_S tensor，同时含 BF16、F32、IQ4_XS、IQ2_S、IQ3_XXS、Q6_K 等格式。巨大的 PLE 表使单一整体 bits-per-weight 数值容易误导。Splash 文档说明 IQ3_S 储存填充从 3.44 扩为 4.06 bits，不对这些数值重新量化；加载时则把 BF16/F16 hyper-connection 投影转换为 Q8_0，本模型有 290 个 BF16 HC 投影 tensor。Strata 的打包转换记录列出空转换列表、compat_bf16=false，但这不构成逐位数值审计。因此这是相同来源 IQ3_S 的引擎对比，并明确存在原生布局、转换与推测解码差异。

## 受控性能探针与模式选择

正式开发前，同一段 8,851 输入 token 的编程提示，生成 512 输出 token，每种模式重复 3 次：Splash 全驻留、Splash 512MiB PLE 缓存，以及现有 Strata 原生模式。九次有效探针 cache_n 均为 0，temperature=0、reasoning=none；原生推测解码路径仍不同。

| 引擎/模式 | n | 平均首事件/s | 冷prefill/tok·s⁻¹ | decode/tok·s⁻¹ | 输入/输出 |
|---|---|---|---|---|---|
| splash/resident | 3 | 3.785 | 2,346.63 | 157.42 | 26,553 / 1,536 |
| splash/ple512m | 3 | 4.085 | 2,173.68 | 151.83 | 26,553 / 1,536 |
| strata/native | 3 | 7.796 | 1,139.03 | 83.36 | 26,553 / 1,536 |

全驻留相较 Splash 512MiB PLE 方案，平均 TTFT 少 0.300s，池化 decode 高 3.68%。对比 Strata，全驻留 prefill 约 2.06×、decode 约 1.89×，该探针的平均首事件延迟约低 51.4%。没有遍历所有内存预算、编译器版本、热稳态或 draft 策略。

## 测量口径与完整性

记录代理保存请求转发时刻、带时间戳 SSE、原生 timings、usage、状态与失败。本报告 TTFT 是首个非空 reasoning_content、content 或 tool_calls delta，可以是思考或工具事件，并不一定是可读的最终正文。正文首字是另一项条件统计：按表格顺序，仅 20/66、30/61、34/149、3/182、16/92、22/64 个请求出现正文。不能据这些不同的小子集给用户可见答案延迟排名。

关键归一化：Splash timings.prompt_n 是输入总量；Strata timings.prompt_n 是本次实际处理的未缓存输入。统一采用 total=usage.prompt_tokens、cached=cache_n、new=total−cached。Strata 的 serve/server.py:5662–5675、test_server.py:3801 断言这一关系；Splash server/metrics.py:235–335 给出口径。初版分析曾从 Strata 已是未缓存量的字段再次减缓存，该评测器错误已纠正，原始响应未改。

原生池化 prefill 采用后端 token 与耗时的总和相除，并非逐请求速度平均。Splash 原生 decode 排除首个发出批次，Strata 用 predicted_n/predicted_ms。观测商用完整输出除以首生成事件到最后 SSE 的区间，首事件可能含多个 token，因此是近似值，表中同时列出。原生 prefill 可能不含前端视觉处理，观测 TTFT 则包含完整转发 HTTP 路径。

614 个正式请求均为 HTTP 200，含 usage、原生 timings 和正常 SSE 完成（18 个 stop、596 个 tool_calls，无 length 结束），共输出 644,413 token，API 总 token 为 55,841,686。其中累计输入 55,197,273，反复计入会话历史，不能当成唯一上下文或本次新计算量。输出包含思考。Strata 不提供单独思考量，记为 null/—，没有记成 0。测量与完整性检查 10,486/10,486 通过，这不是应用功能通过率。

名义 1Hz 采样共保存 11,366 条正式资源样本，含每组开发前 10s 基线；没有大于 2s 的采样间隙。各组平均间隔约 1.004–1.008s。安全终止阈值为连续 15 个 critical 压力样本、原生 footprint/进程树 RSS 超过 115GiB，或 swap 增长超过 8GiB，均未触发。未知量保持 null/空白。未测温度、能耗、逐内核 GPU 占用率或 ANE 利用率。

GPU 利用率属于整块设备，包含浏览器渲染和后台工作。请求区间均值仅保留转发 HTTP 活跃时的样本，仍不能隔离推理进程。系统 CPU 是全机百分比，原生 CPU 以一个核心满载为 100%，两者不能直接比较。Mac 原生 RSS、physical footprint、GPU 驱动 in-use 与系统 used 统计相互重叠且口径不同，不可相加，也不能把 Strata 约 26–30GiB footprint 解读成完整内存需求。

Splash 全机 used 峰值为 106.03–107.81GiB，Strata 为 87.45–93.39GiB。Splash 方块出现 6 个 warning 样本，清明 5 个，均无 critical。每组起点已有约 2.44GiB swap，增长均为 0.00GiB。这证明未测到额外 swap 增长，不代表机器没有 swap。资源汇总包含工具与空闲间隙；请求区间 GPU 均值约 92.79–95.39%，说明不能用全程均值给引擎占用率排名。

## 清明长卷：观赏与接近原作评分

两者均为原创 Canvas2D 绘制，具有持续自动播放、平移缩放、速度和重播。Splash 为 12,000×1,500 世界、153 个移动代理和 63 个静态实体；Strata 为 6,400×1,400、230 个角色及载具实体、12 艘船和 17 个道具。独立观察时钟在 3s 中推进 3s，2× 时在 2s 中约推进 4s，固定相机画面发生变化。桌面与手机缩放适配、真实拖动滚轮和可见控件均有效，无页面异常。

评审使用的故宫参考图是张择端原作的虹桥局部，不是全卷栅格图，也不是像素比对模板。两者取得相同故宫 URL 和文字目标，并可自行查阅。评分依据原作绘画语言：编木虹桥、斜视建筑、活动差异、墨土色、河流与城市叙事，而不是只数物件。候选画面没有在底层嵌入原画。

主要弱点相同：长直河道条带、重复正立面店铺、火柴人物、纵深有限。Splash 建筑线条和桥撑更多，但空水面很大、桥形机械弯折。Strata 市街人群更密、区域按钮方便，但重复群组互相重叠；桥先扁平绘入静态图，再绘船，船会覆盖桥体。两者均未接近原作的木构细节和细密人物叙事；更多实体与输出 token 没有带来高原作还原度。

## 限制与使用建议

每任务、每引擎只有一次随机编程运行，未盲评，没有质量置信区间，也没有引擎转换后的受控数值等价测试。交替顺序降低但未消除时间、后台与温度因素。开始后加入的 300s 工具上限影响电影耗时。代理历史、缓存和图像处理持续分化，六份完成作品全部保留在分母。提供商 fixture 不等于真实 TMDB 验收，未测实体手机性能或长时间无辅助生存流程。故宫栅格参考仅为局部，美学分数属于评审判断。

对此 128GiB M5 Max，如果可以接受全机约 106–108GiB 峰值，已安装的 Splash 全驻留配置有明确的实测吞吐收益。保留原 Strata 服务，可用于实测全机内存较低的工作流与回退。选择哪个运行时都不能省略对生成后端权限、外部适配器、游戏完整状态和视觉还原度的审查。这六份作品呈现了可用机制与具体失败，分数仅描述本轮。
