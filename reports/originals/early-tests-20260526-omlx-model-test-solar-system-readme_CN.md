日期：2026-05-26

本文件夹归档了在配备 128GB 内存的 MacBook Pro M5 Max 上，通过 oMLX 本地 LLM 运行 Hermes Agent 的同提示词基准测试。

## 测试提示词

任务是在 `~/Code` 下创建一个新项目，无需预先配置 git，构建一个动态的 3D 太阳系演示：

- 使用精美的 3D 动画来展示太阳系。
- 包含太阳和 9 颗行星。
- 包含主要卫星，包括月球。
- 对象应根据合理的现实世界规则进行自转/公转。
- 用户可以放大/缩小。
- 点击行星应显示包含文字介绍的弹窗。

## 环境

- 使用 oMLX 本地提供程序的 Hermes Agent
- oMLX 端点：`http://127.0.0.1:8000/v1`
- Hermes 上下文长度：`131072`
- Hermes 最大令牌数：`8192`
- 大多数测试使用的采样参数：`temperature: 0.1`, `top_p: 0.8`, `top_k: 20`, `min_p: 0.01`
- 在适用情况下禁用 Qwen 思考模式

## 各模型备注

### `Qwen3.6-35B-A3B-MLX-8bit`

已归档文件夹：

`solar-system-Qwen3.6-35B-A3B-MLX-8bit`

这是测试中的最佳结果。它生成了一个真实的 Three.js 项目，包含独立的 `index.html`、`styles.css` 和 `script.js`。应用程序渲染正常，交互功能有效，且模型似乎执行了诸如浏览器和控制台检查等实际验证。

优势：

- 整体智能体行为最佳。
- 是真实可运行的项目，而非仅表面层面的文件。
- 视觉场景良好，交互可用。
- 弹窗交互功能正常。
- 在验证方面比其他模型更谨慎。

劣势：

- 尽管提示要求 9 行星，但遗漏了冥王星/Pluto。
- 视觉打磨和比例仍有提升空间。
- 卫星覆盖不够完整。

结论：

将此作为主要的 Hermes 本地 LLM 使用。

### `gemma-4-26b-a4b-it-bf16`

已归档文件夹：

`solar-system-gemma-4-26b-a4b-it-bf16`

该模型生成了一个可运行的单文件 Three.js 演示。Playwright/浏览器检查确认页面已加载，画布已渲染，且点击太阳后弹出了弹窗。

优点：

- 成功运行。
- 包含太阳、9 行星、轨道线、星空背景、缩放/拖拽控件以及弹窗。
- 比失败的 Gemma 31B 结果更整洁。

缺点：

- 仅有一个 `index.html`；没有严谨的项目结构。
- 未初始化 git 仓库。
- 在默认视图中，行星对象在视觉上非常小。
- 仅包含月球；缺少其他主要卫星。
- UI 文本和弹窗内容为英文，而非遵循中文/粤语提示。
- 感觉像是一个快速的最小化演示，而非一个精心完成的任务。

结论：

可作为备选或对比模型接受，但不推荐作为默认模型。

### `Qwen3.6-27B-MTPLX-Optimized-Speed`

已归档文件夹：

`solar-system-Qwen3.6-27B-MTPLX-Optimized-Speed`

该模型速度较快，并尝试了更具结构化的项目，但实现中存在重要的渲染/布局问题。

优点：

- 速度良好。
- 尝试了带有 UI 和弹窗行为的 Three.js 实现。
- 适用于快速的粗略测试。

缺点：

- 存在重要的渲染错误。
- 部分创建的行星对象未正确添加到场景中。
- UI 布局存在问题。
- 最终视觉效果弱于预期。

结论：

仅可作为速度测试模型保留，但在清理后已被移除。不建议用于严肃的 Hermes 代理工作。

### `Qwen3-Coder-Next-8bit`

已归档文件夹：

`solar-system-Qwen3-Coder-Next-8bit`

该模型完成速度非常快，生成的代码在表面上看起来合理。然而，实际的浏览器渲染结果很差。

优点：

- 速度极快。
- 代码中包含了太阳、9 行星、冥王星、月球、控件、标签和弹出窗口。
- 语法/加载检查并非主要问题。

缺点：

- 实际渲染的页面大部分是黑色的。
- 3D 天体几乎不可见，或实际上没有用处。
- 仅将月球作为卫星包含在内。
- 未展示对最终输出的强力验证。

结论：

这是一个很好的提醒，表明编码模型并不自动等同于优秀的智能体模型。不建议将其作为 Hermes 的默认模型。

### `gemma-4-31b-it-8bit`

已归档文件夹：

`solar-system-gemma-4-31b-it-8bit`

本次运行在代码层面失败。它生成了一个 Vite 风格的项目，但 `src/main.js` 被类似行号的前缀和无效片段污染，导致语法错误。

优点：

- 尝试了现代前端项目结构。
- 包含一些相关的太阳系数据。

缺点：

- JavaScript 语法损坏。
- Vite 无法运行该应用。
- 最终结果不可用。

结论：

删除。不值得保留用于 Hermes 智能体使用。

### `Qwen3.6-40B-Claude-4.6-Opus-Deckard-Heretic-Uncensored-Thinking-8bit`

已归档文件夹：

无。由于测试已停止，生成的仓库已被删除。

该模型主要因速度问题被淘汰。在运行过程中，oMLX 的令牌生成速度约为 `9.5 tok/s`，且在运行约 27 分钟后任务仍在进行中。

优势：

- 由于测试在完成前已停止，本次基准测试中未确认任何优势。

劣势：

- 对于 Hermes 代理工作流而言，速度过慢。
- 代理任务需要多次工具调用和迭代推理，因此较低的生成速度会导致问题严重累积。
- 模型名称暗示这是一个经过大量合并/风格调优的模型，这对稳定的工具使用和指令遵循存在风险。

结论：

不要将其用作 Hermes 的默认模型。它已在模型清理过程中被删除。

## 最终决定

最终选定的模型是：

`Qwen3.6-35B-A3B-MLX-8bit`

测试结束后，本地 oMLX 模型存储已清理，仅保留此模型。Hermes 本地配置也已更新，因此 `local-omlx` 仅列出并默认设置为：

`Qwen3.6-35B-A3B-MLX-8bit`

推荐的最终设置：

```yaml
model:
  default: Qwen3.6-35B-A3B-MLX-8bit
  provider: custom
  base_url: http://127.0.0.1:8000/v1
  context_length: 131072
  max_tokens: 8192
```

推荐的 oMLX 采样/设置：

```text
temperature: 0.1
top_p: 0.8
top_k: 20
min_p: 0.01
max_context_window: 131072
max_tokens: 8192
enable_thinking: false
```

## 要点

对于 Hermes Agent 而言，最佳模型并非简单地是最大或最快的模型。最有用的模型需要具备稳定的指令遵循能力、可靠的工具使用能力、足以支持多步骤工作流的速度，以及验证自身输出的严谨性。在本次测试中，`Qwen3.6-35B-A3B-MLX-8bit` 具有最佳平衡性。
