## 结论一 · 视觉闭环打通，且直接产出缺陷发现

上一轮的 OPS-11（mlx-dspark 在加载与请求两处静默丢弃图像）在 MTPLX 上不存在。开工前四道关全验：
服务端收图（1280×720 截图约 900 prompt token / 10s）、`mtplx-request-policy.ts` 扩展不碰图像、
pi 的 read 工具走 image part、随机图内容问答 3/3。

**task-1 它靠「把截图读回来看」抓到一个会让整个验收失败的渲染缺陷**：`world.ts` 的 `pushPrism`
角点按 `[x,z,y]` 存、顶面按 `[x,y,z]` 写，顶面被渲染成竖直墙面，整岛呈「网格篮子」状。
**这类缺陷没有任何断言能抓到**——非空白、非纯色、颜色数、帧间差异全部照常通过。

对照上一轮：R6 十一个美术任务、五个视觉缺陷，pi **0/5**，全部由人看图发现。

## 结论二 · 「根因定位不收敛」这条边界在本轮不成立

上一轮的边界一写的是：**一旦需要在多因素耦合系统里做根因定位，它会持续消耗而不收敛**，
两次失速（AI-01 176m、R7 206m）都必须由评审方在独立副本跑出根因交给它。

本轮 task-4 内部发生两次同形态失速，**两次都自主收敛**：

| | 症状 | 时长 | 真实根因 | 收敛 |
|---|---|---:|---|---|
| 1 | 截图 spec 五个用例全部 `ready()` 20s 超时 | 2h11m | 该 spec 没有 `page.goto`，测试全程停在 `about:blank` | 自主（06:43:04） |
| 2 | 加背包 UI 后整页变暗 3.5 倍 | 2h20m | `ui/backpack.ts` 注入的全局 `.tide-panel` 与 HUD 同名类撞车，四边 offset 同时生效，面板被拉伸成覆盖全视口的 0.88 不透明深色层 | 自主 |

**评审方的介入迟到 89 秒、对结果无贡献。** 时间线：06:43:04 pi 自述
"settle doesn't do a goto at all — I was assuming there was one"；06:44:33 评审方发出根因；
06:44:41 消息到达。**这是一次记录在案的误判**，教训见下。

第二次的推理质量明显高于第一次：从「换假设」升级为**定量反推**——
它由分区亮度 143→39 推出「一块 0.88 不透明深色面板覆盖中心」（143×0.12 + 23×0.88 ≈ 37–39），
再用 git worktree 检出 task-3 基线比对、按文件分组二分、`toDataURL` 原始 canvas（亮）
vs Playwright 整页截图（暗）、`elementsFromPoint` + 计算样式锁定。并且**主动推翻了自己此前
「雾压缩」的误诊，把误诊过程如实写进报告**。

失速的 token 指纹：task-4 思考 74.1 万字符（前三个任务合计 78.6 万）、bash 292 次，
而 edit 仅 96 次——**高思考 + 高探查 + 低改动**。与上一轮 AI-01 的签名一致
（36.9 万思考 vs 其余九任务合计 42 万）。

## 结论三 · 给「看什么」的类别提示，能补上一整类盲区

task-1 评审方独立看图发现四条它漏掉的问题，共同点是**「缺失的东西」与「整体构图」**：
默认相机过远（岛仅占画面 45%）、水塘是轴对齐完美矩形、全场景无投影、海岸线无过渡。
**画面里没有任何东西指向这类问题**——错误的对象会主动吸引注意，「该有却没有的阴影」不会。

task-2 起在投喂里加三类核查（构图 / 缺件 / 几何过规整），它立刻自查出：
天空没有日月亮盘、3 盏路灯排成一条直线，外加 5 条经核实全部属实的打磨项。
task-3 再加第四类（**断言度量的属性与视觉印象是否一致**），当轮即产出最有价值的一次发现：

> **测错图层**：save-ui / 删档 / 损坏提示的「覆盖物改变了画面」断言读的是 WebGL canvas 像素，
> 而面板、toast、弹窗都是 **DOM 覆盖层，canvas 里根本没有**，前后帧 diff = 0。

这是上一轮「探针窗口失效」的同类——**断言在结构上不可能测到目标，且是绿的**。
区别是上一轮靠人算出来，本轮它自查出来。同轮它还自查出手写 PNG 解码器 unfilter 少读一字节
（"压暗"页解出来反而更亮，130 vs 真实 68，靠与 PIL 对拍发现）与 HUD 分钟浮点下取整。

**四类核查建议固化进后续任务书。**

## 仍然存在的老毛病 · 用断言的指标名替代视觉判断

- task-2：断言测 `R−B>30` 的像素数（实测 84），报告写「地面暖色光池清晰」。
  **图上那两片大光池是绿白色冷光**——光打在草地上把草照绿了，只有窗边一小块是暖色。
- task-4：评审方明确要求检查「图标在格子实际尺寸下能不能分辨出**是什么东西**」，
  (d) 节答的是「图标剪影**互异**」。指标与问题不是一回事：两根颜色不同的斜棍能通过「互异」，
  同时作为物体无法分辨。
  （> ⚠️ 但本例中评审方初判「钓竿与树枝无法分辨」经 6× 放大核对后**不成立**——
  钓竿有垂下的鱼线与浮标、树枝弯折带分叉，六个图标均可辨。方法论批评成立，具体案例不成立。）

**这是上一轮「区域统计挡得住有没有、挡不住像不像」的变体**：这次错的不是断言，
是**用断言的指标名去描述观感**。

## 评审方自身的三次失误（方法论）

1. **监视器读了错误的面板。** `zellij action dump-screen` 抓的是**当前聚焦**面板，
   焦点回到评审方自己这边后，读到的是自己状态栏的 `Working on X`，跑了 1h39m 一次未触发。
   第二版改用「jsonl 静默 4 分钟」也误报——pi 一次长思考可超过 4 分钟不写盘。
   **最终判据：session jsonl 末条为 `role=assistant` + `stopReason=stop` + 无 `toolCall`**
   （与上一轮 OPS-09 记载一致，早该直接采用）。另一次守卫误把 pi 输出的
   `Working tree is clean` 当作「仍在忙」。
2. **介入前未重采实施方状态。** 用两小时前开始积累的证据支撑了一个「此刻仍然卡住」的判断，
   而它已在 89 秒前走出来。**通则：介入前必须重新采一次当前状态，旧证据不能证明当下。**
   这与上一轮「假设终端操作生效而不验证」同源。
3. **独立复核污染了被评审的工作树。** 评审方跑 `npx playwright test` 时，截图 spec
   重新生成并覆盖了 8 张已提交截图。若不还原，pi 下次提交会把评审方的运行结果一并提交，
   之后无法分辨哪张图由谁生成。**后续复核一律在 rsync 出的隔离副本中进行。**

评审方还有一次技术误判：怀疑「Playwright 整页截图导致 WebGL 暗帧」，实测 fullPage 与 viewport
**逐像素同亮度**，假设被证伪。真正的分辨性实验是 pi 做的那个——`toDataURL` 原始 canvas
vs 页面截图。**评审方与实施方在同一问题上都猜错过方向，区别只是后者猜错次数更多、每次代价更大。**

**一、耗时由「需要自己搞清楚为什么」的次数决定，不由实现复杂度决定。**
